# 对抗性业务验收 Skill —— 全公司落地引导

版本 2.1.0 ｜ 适用对象：游戏后端开发（语言/引擎不限）｜ 载体：Claude Code Skill

---

## 一、它解决什么问题

玩家的行为不可预测：连点、乱序、卡点、断线、活动开启前就在线。玩家依赖服务端的回包和推送来显示一切——**服务器处理了消息，不等于玩家看到了正确反馈**。任何一个分支漏回包、回错内容、晚回包，玩家看到的就是 bug：轻则困惑重试，重则卡死、刷资源、永久错过奖励。

传统的代码审查回答的是"代码逻辑对不对"；这个 skill 回答的是另一个问题：

> **一个行为完全不可预测的玩家，在每一种操作、每一种时机下，屏幕上看到的东西是对的吗？**

它以「严厉的策划 + QA + 渴望正常反馈的玩家」三个视角，对功能做对抗性业务验收，产出一份带证据（文件:行号）的验收报告。

## 二、包里有什么

```
adversarial-gameplay-acceptance/
├── SKILL.md                                  主流程：三视角 + 七种技术 + 反幻觉铁律 + 报告口径
├── scripts/                                  可执行脚本（Python 3.6+，纯标准库，无需安装依赖）
│   ├── message_map.py                        消息清单机械盘点器：按配置正则扫代码目录，列出
│   │                                         处理器/应答/推送/回调/错误码返回，防手列漏消息
│   ├── verify_report.py                      报告铁律校验器：交付前硬闸门，检查每条发现带
│   │                                         文件:行号、必备章节齐全、覆盖率声明非空
│   └── message-map.example.json              message_map 的配置模板（按项目命名改一次）
└── references/
    ├── adversarial-scenarios.md              对抗场景卡库（十类：并发/顺序/时机/身份/网络/数据/经济/刷新/配置/版本）
    ├── feedback-path-table-template.md       反馈路径表模板 + 脱敏示例
    ├── report-template.md                    验收报告模板 + 严重级别口径
    ├── example-walkthrough.md                端到端验收教学示例（完全脱敏）
    ├── quick-checklist.md                    快速清单（10 分钟版，小改动/hotfix 用）
    └── project-anchors-template.md           框架锚点记录模板（各项目填写自己的）
```

## 二之一、脚本怎么用（可跳过，但强烈建议）

**message_map.py** —— 验收开始时的防漏网。手列"这个功能有哪些消息"容易漏，跑一次脚本对照：

```
python scripts/message_map.py --dir 功能代码目录 --config scripts/message-map.example.json
```

第一次使用：把 `message-map.example.json` 里的 regex 改成你们项目的命名约定（处理器前缀、回包函数名、推送函数名、回调命名、错误码前缀），存到自己项目里复用。脚本扫到而你的清单里没有的条目 = 漏了一条反馈路径。

**verify_report.py** —— 报告交付前的硬闸门：

```
python scripts/verify_report.py 验收报告.md
```

输出 `[ OK ]/[WARN]/[FAIL]` 清单，退出码 0 通过 / 1 不通过。它只查形式（每条发现是否带 文件:行号、章节是否齐全），不懂业务——形式不过，内容免谈。建议纳入团队习惯：报告没跑过这个脚本不许发。

## 三、安装（1 分钟）

把整个 `adversarial-gameplay-acceptance` 文件夹复制到你的 Claude Code skills 目录：

- 个人级（所有项目可用）：`~/.claude/skills/`（Windows: `C:\Users\<你>\.claude\skills\`）
- 项目级（仅当前项目）：`<项目根>\.claude\skills\`

装好后在 Claude Code 里输入 `/adversarial-gameplay-acceptance` 能列出即安装成功。

## 四、怎么用

**时机**：功能开发完成后、提交/提测前。

**触发**：直接说自然语言即可，例如：
- "验收一下刚做的 XX 功能"
- "对抗测试一下这个活动"
- "模拟玩家测一下，检查回包和状态同步"
- "功能写完了，帮我看看玩家会不会遇到 bug"

**建议提供**：功能简述 + 需求文档（如有）+ 涉及的代码位置。给得越全，验收越准。

**等待**：它会真实读代码（协议、处理器、异步回调、推送、错误码逐个读），所以不快——这正是它不产生幻觉的代价。

**产出**：一份验收报告，结构固定：

1. 框架机制确认（本项目回包机制的真实行为，带证据）
2. 需求对照
3. 反馈路径表（每个入口消息 × 每个分支，落到"玩家屏幕表现"）
4. P0/P1/P2 发现清单（每条带 文件:行号 + 玩家场景）
5. 对抗场景卡结果（十类逐条给结论）
6. 需策划 / 客户端 / 运维确认项
7. 已知边界 + 覆盖率声明

## 五、报告怎么读、怎么闭环

| 级别 | 含义 | 处理 |
|---|---|---|
| P0 | 玩家卡死 / 可刷 / 发错人 / 永不回包 | 阻塞上线，必须修 |
| P1 | 回包了但玩家看不懂 / 显示滞后 / 边界漏处理 | 上线前必须处理 |
| P2 | 文案、体验优化 | 可排期 |

- **"需确认项"不是甩锅**：服务端能确证"发了什么"，客户端渲染、策划口径本来就该由对应角色拍板。拿到报告后按表分发给客户端/策划，逐项关闭。
- **"已知边界"要扫一眼**：确认"可接受"是真的可接受，而不是验收者替你做了决定。
- **"覆盖率声明"必须读**：没审的部分不等于没问题。

## 六、反幻觉机制（为什么可以信它的结论）

skill 内置三条铁律，违反即报告作废：

1. 先读代码后下结论——禁止凭记忆、凭"通常这样"；
2. 每条发现必须带 `文件:行号`——**你抽查任何一条结论，直接翻到那个位置核对；拿不出定位的结论不许出现在报告里**；
3. 诚实标注边界——✅已验证 / ⚠️需确认 / ❓无法验证 三档分开，客户端的事不冒充已验收。

另外它强制"先验证框架回包机制再下结论"：不同项目里"处理器返回错误码"的行为完全不同（有的框架自动回错误包，有的不回），skill 不允许假设，必须读框架代码确认，并把结论写进报告开头。

## 七、团队落地三件事

1. **接入开发流程**：把"功能完成后走一次对抗验收"写进你团队的提测前检查单，和 code review 并列。分工：code review 审代码质量与安全漏洞，本 skill 审业务反馈闭环，两者互补不重复。
2. **第一次使用先填框架锚点**：第一次在你的项目里跑，把验证出的框架行为按 `references/project-anchors-template.md` 记成 `references/project-anchors.md`（填好的文件含项目信息，只在团队内留存，勿外传）。之后每次验收直接引用，不重复验证。
3. **持续喂它真实事故**：每出一个线上功能向 bug，把它抽象成一张场景卡，补进 `references/adversarial-scenarios.md` 对应类别。卡库越厚，这个 skill 越锋利——这是它设计上最重要的扩展点。

## 八、边界（别指望它做的事）

- 静态阅读代码，**不运行游戏**；运行时问题（性能、内存、真实网络）不在范围。
- 不替代单元测试与集成测试；它发现的 P0/P1 修复后，仍按正常流程回归。
- 客户端表现只能列"需客户端确认项"，不能替客户端下结论。
- 结论质量取决于你给的范围信息；漏报一个入口消息，它就会漏审那条路径（报告末尾的覆盖率声明会如实反映）。

## 九、FAQ

**Q：跑一次要多久？**
取决于功能规模。一个中等活动（3 条请求消息 + 跨服异步）大约需要完整读十几个文件，分钟级到十几分钟。它慢，但每条结论可抽查。

**Q：怀疑它产生了幻觉怎么办？**
直接要证据："这条结论的 文件:行号 是什么？"然后翻过去核对。铁律 2 保证写不出定位的结论不会进报告；如果你发现它引用了不存在的位置，那一次运行作废，重跑。

**Q：不是 C++ 项目能用吗？**
能。方法论与语言无关（消息契约、状态同步、时序边界、经济对称在任何后端栈都成立）。只是示例偏向后端服务器场景；客户端逻辑不在验收范围。

**Q：可以魔改吗？**
鼓励。骨架（第零原则、三条铁律、Step 流程）建议保留；场景卡库和检查项随你们团队的事故经验随便加。
