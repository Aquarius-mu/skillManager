# 快速清单（10 分钟版）

完整流程（Step 0→6）适合功能开发完成后的正式验收。小改动、hotfix、时间紧迫时，用这份压缩清单过一遍——它保留了最容易出事的检查项，但**不能替代完整验收**，报告里要注明"仅快速清单"。

## 必答题（每题都要有 文件:行号 才能算过）

**回包**
- [ ] 每条请求消息：所有分支（含异步成功路、异常路、空入参、循环全跳过的兜底）都恰好回一次应答？
- [ ] 有没有"提前返回但没回任何包"的路径？
- [ ] 应答字段：客户端要渲染的都填了吗？空列表/0 值时客户端显示什么？

**时机与身份**
- [ ] 成功路径是改完状态之后才回包吗？
- [ ] 异步回调的应答发回给谁？发错人的可能性核对过吗（身份字段、循环变量、下标对齐）？
- [ ] 回调触发时玩家已下线/活动已结束，会怎样？

**刷与绕**
- [ ] 去重/资格检查在发放**之前**吗？
- [ ] 连点两次：第二次被拦且玩家有反馈吗？
- [ ] 限制是服务端拦的，还是只靠客户端藏按钮？直接发包能绕过吗？

**经济与配对**
- [ ] 扣费 ↔ 退款对称吗（折扣也对称）？预检查按折后量算吗？
- [ ] 发奖失败会置"已领取"标记吗？（不许）
- [ ] 每个状态写入点都有对应推送？推送字段包含刚改的字段？
- [ ] 改持久化缓存标记了"已变更待落盘"吗？

**时机边界**
- [ ] 功能开启前就在线的玩家，开启后不重登能正常参与吗？
- [ ] 结束前一秒操作/回调回来时已结束，行为对吗？

**错误码**
- [ ] 新增错误码：客户端有文案吗？没有 = P1，写进需确认项。
- [ ] 会回给玩家的码，玩家能看懂下一步该做什么吗？

**需求对照**
- [ ] 从参考功能复制来的逻辑，逐条对照过新需求文档吗？冲突以新文档为准。

## 输出

快速清单的产出可以简化为：结论 + 发现清单（P0/P1/P2，带 文件:行号）+ 需确认项 + 一行覆盖率声明（"仅快速清单，未做完整反馈路径表与场景卡"）。

交付前同样跑 `python scripts/verify_report.py 报告.md` 过一遍形式闸门。
