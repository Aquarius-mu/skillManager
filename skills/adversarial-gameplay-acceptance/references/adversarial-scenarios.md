# 对抗场景卡库（十一类）

逐类过一遍。每张卡：先问"本功能是否存在这个暴露面"，存在就找代码要答案；不存在就在报告里写"不适用 + 理由"。**禁止整类跳过不写。**

本卡库是活文档：团队每踩一个真实坑，把它抽象成一张卡补进对应类别（只沉淀模式，不写项目细节）。卡的价值来自真实事故，不是想象力。

---

## 一、手速与并发
玩家会连点、双击、多设备同时操作。

- 同一请求连发两次：第二次走哪条分支？会不会重复发奖 / 重复计数 / 重复扣费？
- 去重 / 资格检查是在发放**之前**还是**之后**？（顺序反了 = 可刷。）
- 第一次请求的异步回调还没回来，第二次请求又发出去了：两个回调都会执行吗？状态会错乱吗？
- 多个玩家同时对同一目标操作（抢同一个名额 / 位置 / 奖励）：并发下名额会不会超发？

## 二、顺序异常
玩家不会按你设计的顺序来。

- 跳过前置步骤直接请求后续步骤：会被拒绝并有反馈吗？
- 颠倒顺序（先领取后完成、先结算再操作、未初始化先操作）会怎样？
- 重复领取 / 重复完成请求，第 N 次会怎样？
- 依赖的中间状态被另一个功能改掉 / 清掉时，本功能还能走通吗？
- 同一业务的全部触发路径（主动 / 被动 / 被踢 / 解散 / GM / 离线重登）逐条对齐联动副作用——上轮验收"通过"可能只验了其中一条路径。

## 三、时机边界
时间相关的每个缝隙都要捅一下。

- 活动 / 功能**开启前一瞬间玩家已在线**：开启后不重新登录，能正常参与吗？（资格判定只在登录时做 = 漏判，需要开界面或操作时补判定。）
- **结束前一秒**发起、回调回来时已结束：发不发奖？回什么包？活动结束后**退出类**操作（回城 / 退出场景）还可用吗，还是玩家被错误码困在已结束的场景里？
- 跨天重置瞬间（每日任务 / 限购）：重置前发起、重置后回调，计数算哪天的？
- **(时刻 + 时长) 型操作**：终点要和日边界 / 活动结束做二次校验，只校验起点不校验终点，22 点投 8 小时会跨到次日。
- 惰性过期 / 扫描水位：所有能终止占用 / 会话的边界（主到期点、活跃窗口结束、重置点）都要折进水位，漏折一个，清场就拖到更晚。
- **时钟源统一**：双端各算一遍的时间字段（剩余时间、到期判定、CD），用哪个进程的时钟？GM 跳时间后两端一致吗？兜底逻辑的时钟锚点在谁身上（锚在"首次发生"、没人发生时兜底永不触发）？
- 结算 / 发奖时刻服务器维护重启：进行中的异步会丢吗？重启后状态自愈吗？
- 活动结束时玩家正停留在界面：继续操作会收到什么反馈？

## 四、身份与权限
- 玩家**对自己**使用功能（输入自己的邀请码、给自己投票、攻击自己）：拦得住吗？在哪一层拦？注意"本地没有自己的码"这类绕过。
- 不满足资格的玩家硬发请求：拒绝且有明确反馈吗？
- 同一账号不同区服：数据该共享还是隔离？该隔离的有没有串？
- 跨服功能：目标玩家转服 / 不存在了，会怎样？
- 身份字段在多个角色间传递时（发起者 / 目标 / 被顶替者）：有没有写反的可能？逐个字段核对"这条数据本该给谁"；循环体内有没有误用循环外的变量；多个平行列表靠下标对齐时，下标语义是否还成立。
- 函数处理**另一方玩家**的数据时，所用管理器 / 缓存归属谁（用请求方的管理器查对方 = 恒查不到，规则静默失效）。
- **迟到的操作写过期资源**：客户端拖 N 秒后提交，锁 / 格位可能已过期易主——释放 / 提交路径要与占用路径做对称身份校验，无身份的释放请求可能清掉别人新挂的锁。对方可以是空位或 NPC，超时 / 清锁 / 发奖路径按"无守方"单独走一遍。

## 五、网络异常
- 客户端没收到应答直接重发：服务端能幂等处理吗？
- 断线重连后：进行中的状态还能恢复 / 重建吗？还是玩家看到一半的状态永远卡住？
- 推送丢失（玩家当时离线）：下次登录时状态能从持久化数据重建吗？
- 超时后客户端放弃、服务端继续执行完了：状态与玩家认知不一致，下次打开界面能自愈吗？
- fire-and-forget 的释放 / 取消通知丢包：锁字段残留到自然过期，客户端据此禁用入口——断言"被错误码拦截"前先确认 CS 真的发出去了。
- 跨进程连接"半死"：曾连上、断开后不重连、无任何报错、进程看起来健康——中途杀掉对端再拉起，调用方恢复吗？

## 六、数据极端
- 列表为空：还会回包吗？回空列表还是不回？**空入参的批量查询不一定触发回调，可能永远不回包——必须显式短路回空应答。**
- 达到上限：上限是硬截断还是报错？报错有文案吗？上限语义前后一致吗（保底数还是硬上限）？
- 数值边界：0、1、上限值、跨配置档位。**字段 0 / 缺省值的哨兵语义跨模块会翻转**——上游"0 = 全部剩余"，传到下游变"0 = 不限时长"，中间任何夹取把值算成 0 时，防御兜底可能变成漏洞。
- 非法入参：空字符串、超长字符串、不存在的 id、负数。拒绝且不崩溃、有反馈吗？
- 重复数据：同一对象出现在两个来源（既是好友又是公会成员）：按需求该去重还是该都显示？实现与需求一致吗？多来源合并要按**实体**去重，不只按业务 key——同人被两个切片各报一次 = 幽灵成员。
- 下发体积上界：列表 / 快照类回包和推送，最坏多少条？有没有截断？

## 七、经济对称
凡涉及资源进出，三路必须对称：预检查、实际扣费 / 发放、退款 / 回退。

- 预检查通过 → 实际执行前资源被别的消耗花掉：会透支还是失败？失败有反馈吗？
- 扣费路径打了折，退款路径也打了同样的折吗？（"扣费打折、退款全价"= 刷资源漏洞。）
- **作用集合对称**：扣的时候作用在哪些主体（如 5 支编队），退 / 补必须覆盖同一集合（只补 1 支 = 缺口）。
- 退款晚于周期重置到达：会被下限钳 0 蒸发——方向安全（玩家少得不多得）也要作为策划知情项标注。
- 回包超时 ≠ 操作失败：对端可能已实际执行成功，盲目补偿会与结算回流**双退**——超时后先对账对端实际状态再决定补偿。
- 发放奖励失败：会不会先置了"已领取"标记导致玩家永远领不到？（发奖失败不能置位。）
- 取消 / 中断 / 退款的**所有入口**都覆盖了吗？不只主流程那一个。
- 清锚点 / 清进度类操作：先把累积值结算发放，再清锚点——先清后发 = 吞资源。

## 八、状态刷新
玩家看到的每个数字、红点、列表都来自某次推送或拉取。

- 每个状态写入点：哪个推送让客户端知道？**推送的字段包含刚改的字段吗？**（推送函数往往只推部分字段，不可混用。）
- 同一内容多通道投递（主动 push + 兜底队列 + 回包携带）：在线会不会收到两遍、离线会不会静默丢？消息里有客户端去重键吗？落存判定和投递能力判定是不是同一套判据（isOnline 置位了但推送通道未就绪的窗口）？
- 凡 key / 路由 / 房间由多分量拼出：每个分量的取值来源（客户端传参 vs 服务端权威）与时机一致吗？分叉 = 收不到自己的消息且无自愈。
- "消费即清空"（读时清队列）：以送达确认为前提了吗？两条 at-most-once 通道叠加就是丢失窗口。
- 客户端本地反推 / 换算的显示值：服务端有权威字段兜底吗？钳制 / 封顶后的真实档位下发了吗？
- 一个操作影响多个界面（背包 / 任务 / 红点 / 排行 / 活动面板）：每个界面都刷新了吗？
- 被动变化（被别人顶替、奖励到期、名次下降）：当事人会收到通知吗？还是下次打开才发现？每个改变 A 方数据的事件，枚举所有受影响的 B / C 方，逐个问收到了什么反馈。
- 登录时全量重建与实时增量推送：两者内容一致吗？离线期间发生的服务端事件，登录时会补触发吗（依赖玩家主动拉取的结算，玩家不开界面就永远看不到）？
- 结算 / 发奖的**每条产生结果的路径**（手动 / 自然到期 / 被顶替 / 被动）都要触发全部下游消费者（排行榜上报、任务计数、埋点）——某条路径漏回流，那条玩法就拿不到分。
- 跨进程对同一持久化 key：所有拼 key 方的口径逐个比对（有的带周期 id、有的硬编码、有的内存 key 不含周期），分裂 = 重启后活档换孤儿档。

## 九、运营配置
- 活动未开启 / 已关闭时发请求：拒绝且有反馈吗？
- 配置表缺行 / 填错（奖励为空、上限为 0、时间为 0）：会崩溃、发空奖、还是安全降级？**逐个空字段问"空在代码里是什么语义"**——空 = 1 次、空 = 不限这类反直觉默认要挑出来。
- 同一数据多来源（DB 配置 / 表格 / JSON 缓存 / 多级 fallback）：实际生效的是哪条链？两条链的边界值语义会不会相反（同配 0，一条是"一次"、一条是"无限"）？
- 配置值落在字段类型范围内吗？（超 uint32 上限被静默截断成 19 天，语义完全偏离。）
- 改配置的生效链：谁缓存、读取优先级、要重启谁、等多久、进行中活动的存量数据怎么办——"我改了为什么没变化"先追这条链。
- 功能挂在常驻载体活动下当开关：表配了 ≠ 活动开着，测试环境没开载体 → 整链静默失效，极易误判为代码 bug。
- 配置被删后：玩家 cache 里的孤儿 id 会让功能静默失效，且清理工具自己查同一张表、对孤儿同样失效。
- 表 id / 枚举值改号：全仓 grep 服务端硬编码残留；两套判据列并存时，实际生效路径是哪套、死路径列还在误导配置者吗？
- 功能开关关闭时：入口消息还在被处理吗？回了什么？
- 新旧配置切换（换活动 id、换赛季）：旧数据会污染新周期吗？旧入口还能用吗？

## 十、版本漂移
- 功能从成熟参照实现移植而来：参照方在主体类之外的挂接点（登录、账号变更、过关、结算、数据清理等链路上的钩子）逐个枚举了吗，移植方都有对应物吗？漏一个挂接点 = 漏一整条触发路径。
- 改动落到**共用文件 / 共用结构**（聊天模板、公共推送结构、公共表）：枚举该文件 / 结构的全部消费方逐个验证——改 A 功能波及 B 功能回归，靠客户端反馈才暴露。
- 旧客户端发旧协议（缺新字段）：缺省值安全吗？
- 新客户端发新字段给旧服务端（灰度期）：会报错还是忽略？
- 客户端缓存了过期状态（活动已结束但界面还开着）：操作会被服务端拦住并有反馈吗？
- 新服务端二进制读旧持久化数据（已保存的配置、缓存）：缺字段/缺整块会崩还是会兜底？加载失败是单个活动不可用还是全服活动不可用？改 cache 字段类型后，旧 blob 反序列化报错、新旧二进制不能混跑。
- 环境 / 号段差异：dev 号段可能触发线上不存在的特判过滤（结论不可迁移、也可能掩盖外网问题）；目标 zone 的接入配置（连的哪个 region / Redis / 表）先核对——现象诡异先怀疑连错了环境。
- **svn 提交 ≠ 线上生效**：复测"改了没用"，先核对目标环境二进制的部署时间与修复的提交时间。
- id / 文案类改动：输出跨端影响清单（服务端表、语言表、客户端引用），任一端漏改 = 空文案或被表校验拦截。

## 十一、GM 与运营链路
GM 指令、后台页面、运维工具也是"玩家"，而且是没走协议校验兜底的玩家。

- GM 构造的请求结构逐字段对照正常调用方：漏一个上下文字段（会话 id、开始时间）就拼错目标，在空对象上"成功"执行且无报错。
- GM 回执 "set OK" ≠ 业务生效：链路上每道静默 return 点列出来；判定生效看业务级证据（埋点、push、cache dump），异步操作的回执数量是同步假值。
- GM 通道可能走旁路（不经过真实业务判定链）：旁路测试通过 ≠ 真实链路正常；反过来，真实链路 bug 用 GM 复现不出来。
- GM 清 / 设数据前核对：清的字段就是功能判读的那份数据吗（累计值 vs 时间窗、单字段 vs 多因子）？清完已 push 到客户端的内容、礼包实例、触发条件缓存会联动失效吗？
- GM 跳时间是测试手段也是污染源：时间回拨后一次性粘性标志不复位、偏移文件残留把区服推出活动窗；GM 造的数据无回包痕迹——排查"不可能数据"先查 GM 操作日志。
- 后台页面：查询维度全吗（只有散人没有公会）？空结果有原因还是空白？状态文案有终态出口吗（开完图还显示"待开图"）？时间 / 倒计时用服务端下发值还是前端自算？判成败会被玩家自由文本污染吗（名字里带 ERROR）？
- 批量命令的参数上限：前端限制可被 GM 通道绕过，服务端必须自查。
- 运维工具链的配对（拷贝 / 克隆 / 导入）：造出的数据沿玩家真实链路（登录→选角→进游戏）走一遍；只拷角色不建账号映射 = 空壳号。
- 故障可运维性：出问题后有没有恢复入口（清标志 / 重置的 GM 指令），还是只能删数据重来？
