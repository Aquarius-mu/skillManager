# 工作日早间梳理 — 详细流程与规则

## 输入数据

| 数据 | 来源 |
|---|---|
| 昨日相关消息 + 日历 + 妙记 + 文档活动 + 补采（审批/邮件/视频会议/任务活动） | `collect_all.py --date <昨天>` 的 ctx.json |
| 今日到期任务 | `task +get-my-tasks --complete=false --due-start/--due-end 今天` |
| 逾期未完成任务 | `task +get-my-tasks --complete=false --due-end 昨天` |
| 今日日程 | `calendar +agenda 今天`（ctx.json 里只有昨日日历，今日日程需单独查） |

> ctx.json 里补采字段 `approvals` / `mails` / `vc_meetings` / `task_activity` 各带 `covered` 标记；`covered:false` 表示该渠道未采到，写卡片时不要凭空编造，可在 footer 一句说明覆盖情况。

## 消息归类方法（读 scan.json 时）

每条 relevant 消息带标记：`sent_by_me` / `mention_me` / `name_hit` / `context`（前文上下文）。

1. **昨天@我的消息**：`mention_me=true` 且 `sent_by_me=false` 的消息。
   - 判断处理状态：看该消息之后我有没有回复（同会话后续 `sent_by_me=true` 的消息，或话题已被我推进）。
   - 有回复 → ✅ 已处理；无回复 → ⏳ 待处理，列入"今日待回复清单"。
2. **我负责/参与的事项进展**：`sent_by_me=true` 的消息按会话聚类，识别我昨天推进了什么（修 bug、发版、部署、review、答复问题等）。
3. **别人提到我但我没发言**：`name_hit=true` 且 `sent_by_me=false`——可能是分配给我的事，需列入待确认。
4. **排除**：与我无关的讨论（context 消息仅用于理解上下文，不算工作项）；全局通知类（@all 且不涉及我的具体职责）；闲聊。

## 卡片内容结构（sections 顺序固定）

```
sections[0] 问候 + 一句话总述（"已扫描全部活跃群+私聊"）
sections[1] ## 📋 第一部分：昨日回望（MM-DD 周X）
            ### @我的消息处理情况（表格：时间/来源/发送人/内容摘要/状态）
            ### 我负责/参与事项的进展（按事项列，注明结果）
            ### 遗漏未处理事项（没有就写"无 ✅"）
sections[2] ## 📅 第二部分：今日安排（MM-DD 周X）
            今日日程（无会议就写 ✅）
            今日到期任务（表格，带 applink 链接）
sections[3] ## ⚡ 优先事项排序
            P0 今天必做 / P1 跟进闭环 / P2 清理（逾期待办带链接和逾期天数）
footer     一句话总结当天节奏
```

## 写作规则

- **结果导向**：写"修复了X、发版完成、已确认Y"，不写"沟通了X、讨论Y"。
- **精准第一**：只写与我直接相关的；拿不准是否与我相关的，标注「待确认」。
- **逾期天数**要算出来（今天日期 - 截止日期）。
- **任务链接**用待办返回的 `url` 字段（applink），点击可跳转。
- **预告**：从消息中识别未来的约定（如"周五10点前到"），放今日安排的"📌 预告"。
- 表格在飞书卡片 lark_md 中用标准 markdown 表格语法。
- 单个 section 别超过 ~1200 字；内容多时合并同类项。

## 自动化（automation）场景补充

- 任务 prompt 里通常带"先判断工作日"——周末直接回一句"今天是周末，不发送"，不拉数据。
- 发送后向用户汇报执行摘要（昨日闭环项、今日重点、逾期提醒），不要只说"已发送"。
