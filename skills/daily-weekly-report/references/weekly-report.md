# 周报生成 — 详细流程与模板

## 输入数据

优先用一站式采集（消息 + 日历/妙记/文档 + 补采，全部合并为一个 JSON）：

```bash
python scripts/collect_all.py --start <周一YYYY-MM-DD> --end <周五/今天YYYY-MM-DD> --out <tmp>/week.json
```

`week.json` 顶层字段：
- `messages.relevant`：全周与我相关的消息（按时间排序，带会话名、发送人、标记）
- `messages.by_chat`：分会话统计，用于快速定位主要工作阵地
- `calendar` / `minutes` / `documents`：本周日程、妙记、文档活动（去重）
- `approvals` / `mails` / `vc_meetings` / `task_activity`：补采的审批/邮件/视频会议/任务活动，各类含 `covered` 标记

只扫消息时的降级方案（不要日历/妙记/文档）：`scan_messages.py --start <周一> --end <周五/今天>`。

辅助补充（可选，让周报更完整）：
- 本周完成的待办：`lark-cli task +get-my-tasks --complete=true --created_at <周一>`（collect_all 的 task_activity 已覆盖大部分）
- 本周日程/会议：`lark-cli calendar +agenda --start <周一> --end <周五>`（collect_all 的 calendar 已覆盖）

## 归类方法

1. **按项目/主题聚类**：同一个群、或围绕同一功能/需求/线修的消息合并为一个事项。
   典型聚类线索：会话名（需求同步群/版本群/线修群）、功能关键词、协议/单号（线修 ID、story 链接）。
2. **只算我参与的**：我主动发言、或明确回应过的才算。纯围观、别人聊我没说话的不算。
3. **角色识别**：从消息内容判断我的工作性质（开发/指导新人/排查问题/发版运维/方案评审），按对应逻辑组织。
4. **噪音过滤**：闲聊、吐槽、股票/游戏/租房话题、纯表情、"收到/好的"、系统消息一律不进周报。
   （例外：若闲聊体现了跨团队关系且用户希望保留，放"其他"一笔带过。）

## 周报模板（markdown，写入飞书文档）

```markdown
# <姓名> 周报（YYYY-MM-DD ~ YYYY-MM-DD）

## 本周概览

本周主力投入 **【主线1】**，同时推进 **【主线2】**……（1-2 句总览，点出 2-3 件大事）

**关键进展：**
- 主线1：完成了……
- 主线2：解决了……
- 其他：处理了……

---

## 工作事项

### 一、【项目/事项 A】
**来源群：** <群名>
**协作方：** 姓名(英文名)（角色，如客户端/策划/QA）

**<工作分类1，如：功能开发>：**
- 具体做了什么（技术细节、协议名、错误码、方案决策点原样保留）

**<工作分类2，如：问题排查与修复>：**
- ……

**<工作分类3，如：测试与联调>：**
- ……

---

### 二、【项目/事项 B】
（同上结构；带新人指导类事项要写清指导内容）

---

### 三、其他
- 杂项、协助、跨团队沟通，合并列出

---

## 跨团队协作

- **与<团队/角色>（姓名）**：就什么事项协作，一句话说明
```

## 写作规则（重要）

1. **结果导向**：每条用"完成了X / 推进了Y / 解决了Z"表述，不写"讨论了一下、沟通了一下"。
2. **突出产出**：写清具体产出物——新增的协议/字段/GM命令/错误码、发版的区服、修复的 bug 根因。
3. **保留专业术语**：协议名（Cmd_Xxx_CS/SC）、错误码（Error_Xxx = 12329）、区服号、表名、分支名原样保留，不翻译不解释。
4. **诚实**：数据少就如实写"本周沟通较少"；不确定的标「待确认」；不编造。
5. **层级清晰**：同一事项下的子工作用粗体小标题分组（功能开发/问题排查/测试联调/方案评审等）。
6. **协作方要具体到人**：姓名(英文名) + 角色。

## 写入飞书文档

周报 md 文件**首行必须是 `<title>标题</title>`**，然后（cd 到文件所在目录，用相对路径）：

```bash
lark-cli docs +create --doc-format markdown --content @week_report.md --as user
```

- ⚠️ 实测要点：标题放 content 首行的 `<title>...</title>`，**不要用 --title flag**（新版已废弃）；`@file` 只接受相对路径。
- 返回 JSON 里取 `data.document_id`，链接为 `https://<your-tenant>.feishu.cn/docx/<document_id>`（或取 `data.url`）。
- **写操作必须先给用户看周报全文，确认后再创建**（自动化场景按任务权限直接创建）。
- 用户给了目标 wiki/文件夹 token 时加 `--parent-token`。
- 创建成功后把文档链接发给用户（可直接在对话里给链接）。
